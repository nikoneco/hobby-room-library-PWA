## 8. series registry v2 列構成

### series_master_v2

| 列 | ヘッダー | 用途 |
|---|---|---|
| A | series_id | シリーズ本体の不変ID。ジャンルはこのIDへ紐づく |
| B | シリーズ名 | カタカナ・大小文字等を保った人向け表示名 |
| C:G | J-* | ジャンル5枠。genre_masterの入力規則を使用 |
| H | 蔵書数 | 同じseries_idへ解決された現在の冊数 |
| I | 状態 | ACTIVE等の運用状態 |
| J | 更新日時 | 登録・更新時刻 |
| K | canonical_key | series_key_auto由来の機械照合キー。通常は直接編集しない |

### series_alias_v2

| 列 | ヘッダー | 用途 |
|---|---|---|
| A | alias_key | 目録X、旧キー、誤字訂正前後のキー |
| B | series_id | alias_keyが属するシリーズ本体 |
| C | 由来 | MIGRATION_X / LEGACY_TITLE_PREFIX / TITLE_EDIT / AUTO_SIGNATURE等 |
| D | match_signature | 記号・空白・大小文字・かな差を吸収する照合署名 |
| E | 蔵書数 | 登録時点の該当冊数 |
| F | 更新日時 | 別名登録時刻 |

タイトル訂正時は、編集前Xが解決していたseries_idへ編集後Xを新しいaliasとして追加する。編集後Xが別の既存series_idへ解決する場合は自動統合せず旧キーを維持し、series_match_review_v2へ記録する。新刊の表記差は、照合署名が一意に一致する場合だけ自動吸収する。曖昧な候補はseries_match_review_v2へ残し、勝手に統合しない。

Webアプリ内のシリーズ集約キーは、registry有効時はX文字列ではなくseries_idを使う。X列は照合候補として保持するため、タイトル誤字訂正や代表キー変更で既存ジャンルとシリーズ集約が切れない。

## 12. キャッシュ破棄が必要な変更

現行実装では、目録シート編集時は列を問わず onEdit で clearLibrarySearchCache_() が呼ばれる。genre_masterとseries_masterは全編集、データはB列の出版社候補とL2の最終行ヒントを含む編集でも破棄する。

Web表示に影響するため、特に破棄が必要な列:

- I タイトル
- K 作者
- L 出版社
- M 本棚-1
- N 本棚-2
- O 発売日
- P 値段
- Q レーベル
- S ISBN
- T 備考
- U 読み仮名
- V UUID
- W ジャンル
- X series_key_auto
- Y あらすじ_RAW
- AA FALLBACK_IMAGE_URL
- AB FALLBACK_IMAGE_SOURCE

J画像とRバーコードはWeb表示の主要データには直接使われないが、現行実装では目録編集ならまとめてキャッシュ破棄される。

series_master B:Gの編集では、キャッシュ破棄前にX列の全件整合性修復を行う。処理中はScript Propertiesへdirtyフラグを残し、正常完了後だけ解除する。変更0件ではX列のsetValuesを呼ばない。

## 13. 行ズレ事故が起きやすい列

| 列 | 理由 |
|---|---|
| Y/Z | あらすじRAW/SOURCEが本とズレると誤表示になる |
| AA/AB | fallback画像URL/SOURCEが本とズレると別本の表紙になる |
| X | series_key_autoがズレるとシリーズ一覧が壊れる |
| W | ARRAYFORMULA列。ソート時にスピル範囲が邪魔になるため一時退避している |
| I/S/K/L | タイトル・ISBN・作者・出版社は各種キーの基準 |
| B:AB全体 | sortMainRowsByTitle_ はB:ABを一体でソートする設計。範囲を狭めると事故りやすい |

## 15. 要注意メモ

- 目録!W1 のジャンル式が series_master を参照しているため、GASだけ見ていると series_master 依存を見落とす。
- CONFIG.COL はI/K/J/Sなど一部だけ定義され、L/M/N/O/P/Q/T/Rは CONFIG.IDX 側にしかない。
- 列追加や読み取り範囲変更をする時は、CONFIG.COL と CONFIG.IDX の対応崩れが最も危険。
- V列UUIDは既存値を再生成しない。行コピーで重複した場合は編集対象側だけ新しいUUIDへ置き換える。
- X列はW列の再計算待ちに依存せずseries_master B:Gから判定する。series_masterのA列正規化式とB:Gの対応規則を変える場合は、buildSeriesMasterExtraLookup_の規則と回帰fixtureも同時に更新する。
